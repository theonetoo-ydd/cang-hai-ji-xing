# MVP 定义

## 一句话目标

验证“明代航海贸易”作为核心循环是否值得继续开发。

## 玩家最小体验

玩家从一个港口开始，拥有有限资金与货舱。通过观察不同港口的价格差异，选择商品并买入，承担航行时间与随机风险，到另一港口卖出，形成利润或亏损。

## MVP 必须回答的 4 个问题

1. 买卖是否足够清楚？
2. 航线选择是否能产生决策？
3. 风险是否能让贸易结果出现变化？
4. 玩家是否自然产生“再跑一趟”的动机？

## 必须包含

- 3 个测试港口；
- 6 种测试商品；
- 基础资金；
- 单船；
- 货舱容量；
- 买入与卖出；
- 航行时间；
- 3 类随机事件；
- 盈亏结算；
- 单档存档。

## 明确不包含

MVP 阶段不实现：
- 海战系统；
- 船队编成；
- 国家外交；
- 多势力 AI 经济；
- 复杂人物养成；
- 大型剧情；
- 动态天气和洋流物理模拟；
- 多人游戏。

## 成功标准

完成一次完整流程：

```text
港口 A
  ↓ 买入
货舱变化 / 资金变化
  ↓ 出航
航行时间推进 / 可能发生事件
  ↓ 抵达
港口 B
  ↓ 卖出
货舱变化 / 资金变化 / 显示利润
```

只要这个循环稳定、可重复、无明显阻塞，就进入下一阶段。
